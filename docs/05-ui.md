# Интерфейс

Интерфейс построен по MVVM: вся логика экрана живёт в модели представления,
разметка только привязывается к её свойствам и командам. В коде за разметкой
пусто — кроме трёх мест, где иначе нельзя.

## Основа MVVM

Готовой библиотеки нет, вместо неё четыре файла в `Mvvm/`.

### `ObservableObject`

```csharp
protected bool Set<T>(ref T field, T value, [CallerMemberName] string? propertyName = null)
{
    if (EqualityComparer<T>.Default.Equals(field, value)) { return false; }

    field = value;
    Raise(propertyName);
    return true;
}

protected void Raise([CallerMemberName] string? propertyName = null) =>
    PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
```

`Set` возвращает `bool` — удобно, когда на изменение нужно что-то повесить:

```csharp
public PeriodOption SelectedPeriod
{
    get => _selectedPeriod;
    set { if (Set(ref _selectedPeriod, value)) { Reload(); } }
}
```

`Raise()` без аргумента внутри сеттера подставит имя этого свойства — так работает
откат значения в поле ввода: поле не меняем, но сообщаем, что оно «изменилось»,
и привязка перечитывает прежнее значение.

### `RelayCommand` и `RelayCommand<T>`

Обычная реализация `ICommand`. Доступность пересчитывается **явно**, вызовом
`RaiseCanExecuteChanged()`, а не через `CommandManager.RequerySuggested`: так видно,
кто и когда включает кнопку.

```csharp
StartCommand = new RelayCommand(Start, () => _timer.IsIdle);
```

У версии с параметром доступность зависит только от типа параметра, поэтому
её `CanExecuteChanged` — пустая заглушка.

### `ITicker` и `DispatcherTicker`

```csharp
internal interface ITicker
{
    event EventHandler? Tick;
    void Start();
    void Stop();
}
```

Источник тиков вынесен за интерфейс, чтобы `TimerViewModel` можно было проверить
тестом: в приложении это `DispatcherTicker` с интервалом 100 мс, в тесте — `FakeTicker`,
который дёргается вручную.

Разделение получается такое: **`TimeProvider` отвечает за «сколько прошло»,
`ITicker` — за «когда пересчитать экран»**. Первое — вопрос домена, второе — вопрос
интерфейса, и путать их не стоит.

## Модели представления

```
MainViewModel
├─ TimerViewModel      таймер и его кнопки
├─ TodayViewModel      «сегодня»: часы, количество, список
│   └─ SessionListViewModel
│       └─ SessionRowViewModel ×N
├─ StatsViewModel      период, диаграмма, легенда, список
│   ├─ SessionListViewModel
│   ├─ ChartColumnViewModel ×N  →  ChartSegmentViewModel ×M
│   ├─ GridLineViewModel ×N
│   └─ LegendItemViewModel ×N
└─ SettingsViewModel   длительности, граница суток, справочник типов
```

### `MainViewModel`

Знает, какой экран открыт, и раздаёт обновления.

```csharp
public bool IsStatsVisible
{
    get => _isStatsVisible;
    private set
    {
        if (!Set(ref _isStatsVisible, value)) { return; }

        Raise(nameof(IsTimerVisible));
        IsSettingsOpen = false;
        ReloadVisibleScreen();
    }
}
```

Состояние экрана — **нормальное булево свойство**, а не `Visibility` какого-то элемента
разметки. В разметке оно превращается в видимость штатным `BooleanToVisibilityConverter`.

`ReloadVisibleScreen()` перечитывает только открытый экран. Вызывается, когда:

- завершилась помидорка (`Timer.WorkCompleted`);
- поменялся справочник типов (`Settings.CatalogChanged`);
- поменялись настройки (`AppSettings.Changed`) — например, граница суток;
- окно вернули из трея (`App.RestoreFromTray`);
- отработал запрос в консоли (`ReloadAfterSql`).

`SqlConsoleRequested` — событие наверх: модель не создаёт окон, этим занимается `App`.

### `TimerViewModel`

Обёртка над `PomodoroTimer`: держит ссылку на доменный таймер и переводит его
состояние в строки для экрана.

```csharp
public void Advance()
{
    TimerStep step = _timer.Advance();

    if (step.Completed is WorkSession session) { WorkCompleted?.Invoke(this, session); }
    if (step.Event != TimerEvent.Nothing)      { PhaseFinished?.Invoke(this, EventArgs.Empty); }

    Refresh();
}
```

`Refresh()` — единственное место, где пересчитываются все видимые свойства:
`TimeText`, `PhaseText`, `HintText`, `PauseText`, `Progress`, плюс `IsWorking`,
`IsResting`, `IsPaused` и доступность трёх команд. В покое он же останавливает тикер
и показывает на циферблате выставленную длительность работы.

Булевы `IsWorking`/`IsResting` вместо свойства с перечислением — чтобы в разметке
были простые `DataTrigger` на `True`, без возни с приведением типов в XAML.

Звук таймер не играет: он поднимает `PhaseFinished`, а `Chime.Play()` висит на этом
событии в `App`. Так модель остаётся без побочных эффектов и её можно создать в тесте,
не опасаясь, что он загудит.

### `SessionListViewModel` и `SessionRowViewModel`

Один и тот же список используют оба экрана: «сегодня» — без колонки даты,
статистика — с ней. Флаг `ShowsDate` раздаётся и списку, и каждой строке.

`Load` аккуратно отписывается от старых строк перед тем, как выбросить их:

```csharp
foreach (SessionRowViewModel row in Rows)
{
    row.Changed -= OnRowChanged;
    row.DeleteRequested -= OnRowDeleteRequested;
}
```

Строка сама в базу **не удаляет** — она поднимает `DeleteRequested`, а удаляет владелец
(`TodayViewModel` или `StatsViewModel`), потому что после удаления нужно ещё и
перечитать экран.

Правка минут живёт в сеттере:

```csharp
public string Minutes
{
    get => _minutes;
    set
    {
        if (!TryParseMinutes(value, out int minutes)) { Raise(); return; }

        string normalized = Format.Integer(minutes);
        if (normalized == _minutes) { Raise(); return; }

        _minutes = normalized;
        DurationSec = minutes * 60;
        _store.UpdateDuration(Id, DurationSec);
        Raise();
        Changed?.Invoke(this, EventArgs.Empty);
    }
}
```

Мусор и выход за границы (0…1440) молча откатываются: `Raise()` без изменения поля
заставляет привязку перечитать прежнее значение. Диалог на каждую опечатку в списке
раздражал бы сильнее, чем молчаливый откат.

Поля в конструкторе заполняются **напрямую, минуя свойства**:

```csharp
// Поля заполняем напрямую: через свойства это выглядело бы как правка
// и записалось бы в базу при первой же отрисовке строки.
_minutes = Format.Minutes(session.Duration);
_selectedOption = Type.Length == 0 ? WorkTypes.NoTypeOption : Type;
```

Это не стилистика, а исправленная ошибка: в прежней версии строка с типом, записанным
в другом регистре, молча переписывала историю при первой же отрисовке списка.
На это есть тест `Showing_a_row_never_writes_to_the_store`.

Если тип записи больше не числится в справочнике, он всё равно добавляется в список
вариантов — иначе выбор нельзя было бы вернуть обратно.

### `StatsViewModel`

Самая большая модель (около 300 строк), и почти всё в ней — раскладывание результата
`StatsCalculator` по коллекциям, на которые подписана разметка.

Поведение легенды задано словами и реализовано дословно:

```csharp
public void ToggleType(string type, bool shiftHeld)
{
    List<string> allTypes = [.. Legend.Select(item => item.Type)];
    bool isShown = !_hiddenTypes.Contains(type);
    bool isOnlyShown = isShown &&
        allTypes.TrueForAll(other => WorkTypes.Comparer.Equals(other, type) || _hiddenTypes.Contains(other));

    if (shiftHeld)      { if (isShown) { _hiddenTypes.Add(type); } else { _hiddenTypes.Remove(type); } }
    else if (isOnlyShown) { _hiddenTypes.Clear(); }
    else                { _hiddenTypes.Clear(); _hiddenTypes.UnionWith(allTypes.Where(...)); }

    Refresh(rebuildList: true);
}
```

- обычный клик оставляет **только нажатый** тип;
- клик по единственному включённому возвращает **все**;
- Shift+клик добавляет или убирает **один** тип.

Shift+клик по последнему включённому гасит всё: экран показывает ноль часов
и «За этот период ничего не отработано». Это оставлено буквальным — правило
«Shift переключает один тип» без исключений.

Состояние фильтра живёт **только в памяти**: это взгляд на данные, а не настройка,
и после перезапуска снова показано всё.

Модель узнаёт про Shift сама:

```csharp
ToggleTypeCommand = new RelayCommand<LegendItemViewModel>(item =>
    ToggleType(item.Type, Keyboard.Modifiers.HasFlag(ModifierKeys.Shift)));
```

Да, это `System.Windows.Input` в модели представления. Слой и так знает про WPF
(в нём кисти для диаграммы), зато сама `ToggleType(type, shiftHeld)` остаётся
обычным методом с параметром — и проверяется тестом напрямую.

### `SettingsViewModel`

Три поля ввода (работа, отдых, граница суток) отдаются разметке **строками**,
потому что в поле можно набрать что угодно:

```csharp
public string WorkMinutes
{
    get => Format.Integer(_settings.WorkMinutes);
    set => SaveMinutes(value, minutes => _settings.WorkMinutes = minutes);
}
```

Разбор, проверка диапазона и сохранение — в сеттере; `Raise()` в конце либо нормализует
набранное (`007` → `7`), либо откатывает мусор. Диалога с руганью нет: в прежней версии
он выскакивал при нажатии «Пуск», если в поле оказался мусор; теперь мусор туда
просто не доезжает.

Справочник типов — `ObservableCollection<string>`, перечитывается из базы после
каждого добавления и удаления. `CatalogChanged` уходит наверх, чтобы открытый экран
пересобрал списки вариантов в строках.

### Модели для диаграммы

`ChartColumnViewModel`, `ChartSegmentViewModel`, `GridLineViewModel`, `LegendItemViewModel` —
неизменяемые объекты с `required`-свойствами, которые пересоздаются при каждом пересчёте.
Уведомления им не нужны: меняется не объект, а вся коллекция.

`GridLineViewModel.Top` уже содержит поправку на половину высоты подписи — чтобы цифра
стояла по центру линии, а не над ней:

```csharp
Top = ChartLayout.GridLineTop(hours, scale, _plotHeight) - LabelHalfHeight
```

### Переключение экранов

```xml
<Grid Margin="18" Visibility="{Binding IsTimerVisible, Converter={StaticResource BoolToVisibility}}">
```

Оба экрана лежат в одном `Grid` друг поверх друга, видимость переключается привязкой.
Таймер при этом продолжает идти: он живёт в модели, а не в разметке.

Важная мелочь: видимость стоит на **обёртке**, а не на самом `views:StatsView`.
Если повесить её на элемент, которому тут же меняют `DataContext`, привязка видимости
начнёт искать свойство в новом контексте и ничего не найдёт.

### Общий список

Ширины колонок заданы **один раз** — через `Grid.IsSharedSizeScope` и `SharedSizeGroup`:

```xml
<ColumnDefinition Width="Auto" SharedSizeGroup="DateColumn" />
<ColumnDefinition Width="Auto" SharedSizeGroup="EndColumn" />
<ColumnDefinition Width="Auto" SharedSizeGroup="MinutesColumn" />
<ColumnDefinition Width="*" />
<ColumnDefinition Width="Auto" SharedSizeGroup="DeleteColumn" />
```

Заголовок и все строки состоят в одних группах, поэтому разъехаться не могут.
В прежней версии ширины были прописаны числами в четырёх местах, и правка одного
из них ломала выравнивание.

Колонка даты на экране «сегодня» не просто пустая, а `Collapsed` — свёрнутый элемент
не занимает места вместе со своими отступами.

Корзина появляется при наведении на строку:

```xml
<DataTemplate.Triggers>
    <Trigger SourceName="RowRoot" Property="IsMouseOver" Value="True">
        <Setter TargetName="DeleteButton" Property="Visibility" Value="Visible" />
    </Trigger>
</DataTemplate.Triggers>
```

У корневого `Grid` строки стоит `Background="Transparent"` — без него наведение
не ловится над пустыми местами между элементами.

### Диаграмма

Три слоя в одном `Grid`:

1. подпись «За этот период ничего не отработано» — по привязке к `IsEmpty`;
2. сетка: `ItemsControl` с `Canvas` в качестве панели, позиция задаётся через
   `ItemContainerStyle` → `Canvas.Top`; слой не ловит мышь (`IsHitTestVisible="False"`),
   поэтому не перехватывает подсказки столбиков;
3. столбики: `ScrollViewer` с горизонтальной прокруткой и `StackPanel` внутри.

Отступ `Margin="36,0,0,0"` у прокрутки — та же `AxisWidth`, что и в `ChartLayout`.
Это единственное место, где константа продублирована: в разметке её значением
нельзя воспользоваться напрямую.

### Легенда

Плашка — обычная `Button`, а не `ToggleButton`. Включённость рисуется `DataTrigger`
по `IsShown`, а не внутренним состоянием кнопки:

```xml
<DataTrigger Binding="{Binding IsShown}" Value="False">
    <Setter TargetName="Chrome" Property="Opacity" Value="0.35" />
</DataTrigger>
```

У `ToggleButton` состояние переключалось бы само, до того как модель решит, что делать
с фильтром, — и на кадр показывало бы неправду.

Команда достаётся у предка, потому что `DataContext` плашки — элемент легенды:

```xml
Command="{Binding DataContext.ToggleTypeCommand, RelativeSource={RelativeSource AncestorType=ItemsControl}}"
CommandParameter="{Binding}"
```

### Меню настроек

`Popup` с `StaysOpen="False"`, привязанный к `IsSettingsOpen` в обе стороны:
клик мимо меню закрывает его и возвращает свойство в `false`.

Enter в поле нового типа обходится без кода за разметкой:

```xml
<TextBox Text="{Binding NewTypeName, UpdateSourceTrigger=PropertyChanged}">
    <TextBox.InputBindings>
        <KeyBinding Key="Enter" Command="{Binding AddTypeCommand}" />
    </TextBox.InputBindings>
</TextBox>
```

`UpdateSourceTrigger=PropertyChanged` здесь обязателен: без него к моменту нажатия
Enter модель ещё не знает набранного текста.

## Три исключения

Код за разметкой есть ровно в трёх местах.

### Ввод с клавиатуры

`SessionListView.xaml.cs` и `SettingsView.xaml.cs`:

```csharp
private void OnDigitsOnlyInput(object sender, TextCompositionEventArgs e)
{
    e.Handled = !Digits().IsMatch(e.Text);
}

[GeneratedRegex("^[0-9]+$")]
private static partial Regex Digits();
```

Фильтр нецифр — это обработка ввода, а не логика. Он не является проверкой:
вставка из буфера `PreviewTextInput` не вызывает, и вставленный мусор отсечёт
уже модель. Enter в ячейке снимает фокус (`Keyboard.ClearFocus()`), а привязка
с `UpdateSourceTrigger=LostFocus` на этом и срабатывает.

### Размер панели диаграммы

`StatsView.xaml.cs`:

```csharp
public StatsView()
{
    InitializeComponent();
    DataContextChanged += (_, _) => PushPlotSize();
}

private void OnChartHostSizeChanged(object sender, SizeChangedEventArgs e) => PushPlotSize();

private void PushPlotSize()
{
    if (ChartHost.ActualWidth > 0.0 && ChartHost.ActualHeight > 0.0 && DataContext is StatsViewModel viewModel)
    {
        viewModel.SetPlotSize(ChartHost.ActualWidth, ChartHost.ActualHeight);
    }
}
```

`ActualWidth` только для чтения, привязать его к модели нечем. Два обработчика,
а не один, потому что размер и `DataContext` приходят в непредсказуемом порядке:
какое событие окажется вторым, то и отдаст модели окончательный размер.
С одним только `SizeChanged` диаграмма один раз строилась с нулевой шириной
и такой и оставалась.

### Выделение в консоли

`SqlWindow.xaml.cs`:

```csharp
viewModel.Run(QueryBox.SelectionLength > 0 ? QueryBox.SelectedText : null);
```

`TextBox.SelectedText` не является свойством зависимости, привязать его нельзя.
Здесь же обрабатываются F5 и Ctrl+Enter.

## Стили и темы

Все цвета — в `Themes/Colors.xaml`, в разметке нет ни одного шестнадцатеричного
значения. Токены именованы по роли, а не по виду:

| Имя | Где используется |
|---|---|
| `BackgroundBrush` | фон окна и полей ввода в рамке |
| `PanelBrush` | карточки-панели |
| `SurfaceBrush` | вдавленные области: списки, диаграмма |
| `WellBrush` | самое тёмное: дорожка прогресса, поле в фокусе |
| `ControlBrush` | плоские кнопки |
| `ControlQuietBrush` | кнопки верхней панели |
| `ControlHoverBrush` | подсветка под курсором |
| `AccentBrush`, `AccentSoftBrush`, `AccentStrongBrush` | акцент, его полупрозрачные варианты |
| `RestBrush` | фаза отдыха |
| `TextBrush`, `MutedBrush`, `BorderBrush` | текст и рамки |
| `ThumbBrush`, `ThumbHoverBrush`, `ThumbDragBrush` | ползунок прокрутки |

Остальные словари: `Text.xaml` (стили текста и панелей), `Buttons.xaml`,
`Inputs.xaml` (поля и выпадающие списки), `ScrollBar.xaml`, `Common.xaml`
(конвертер видимости).

Важная тонкость WPF: **словарь, который пользуется чужими ресурсами, обязан сам их
подключить**. Поэтому в начале `Text.xaml`, `Buttons.xaml`, `Inputs.xaml` и
`ScrollBar.xaml` стоит:

```xml
<ResourceDictionary.MergedDictionaries>
    <ResourceDictionary Source="Colors.xaml" />
</ResourceDictionary.MergedDictionaries>
```

Без этого `StaticResource` внутри словаря не найдёт цвет, даже если тот подключён
на уровне приложения. На окна и экраны это правило не распространяется: они
видят всё, что лежит в `App.xaml`.

Стандартные стили `ComboBox` и `ScrollBar` переопределены целиком — встроенные
светлые и в тёмной теме выглядят чужими.

## Доступность

У кнопок, состоящих из одного значка (шестерёнка, стрелка назад, корзина),
проставлен `AutomationProperties.Name`: без него чтец с экрана произнесёт
символ из приватной области Unicode. Подписи есть и у полей ввода настроек,
и у полей консоли — заодно по ним удобно находить элементы в тестах интерфейса.
